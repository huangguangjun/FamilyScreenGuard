# 纯血鸿蒙儿童隐私守护 App：设计规格

**状态：** 已确认，待用户审阅  
**目标平台：** HarmonyOS NEXT（纯血鸿蒙）  
**范围：** 第一版（本地、单设备、家庭使用）

## 1. 目标与边界

本应用用于在监护人指定时段内，阻止已登记儿童偷看或操作安装本应用的手机。时段内，应用通过前置摄像头低频检测已登记的人脸；识别命中后立即显示全屏黑色隐私遮罩。解除遮罩、暂停守护和修改设置均须通过监护人 PIN。

第一版采用普通第三方应用可实现的前台守护模式，不尝试调用企业设备管理（MDM）锁屏能力。它能接管应用内界面和日常使用路径，但不能承诺拦截电源键、紧急呼叫或所有系统级入口。

## 2. 非目标

- 不录制或保存实时摄像头画面。
- 不上传照片、人脸特征或检测记录。
- 不提供远程控制、账号体系、云同步或广告。
- 不把人脸检测结果用于身份追踪、行为分析或惩罚。
- 不承诺替代系统锁屏或企业 MDM 管控。

## 3. 用户与权限

监护人是唯一设置者，负责登记儿童照片、创建 6 位 PIN 和配置时段。儿童或普通使用者不能在未输入 PIN 的情况下暂停守护、退出拦截或查看、修改照片与规则。

首次设置时应用必须以清楚的中文解释相机的用途、处理频率、仅本机处理和不保存视频，并在取得相机权限后才可启用守护。使用过程中遵守系统相机隐私指示。

## 4. 核心流程

1. 监护人设置 PIN，添加每名儿童的 3–5 张正脸参考照片，并设置按星期重复的时间段。
2. 到达时段开始时间，应用发送“守护即将开始”的通知并显示 1 分钟倒计时。
3. 监护人在倒计时内输入 PIN 后，可选择“立即开始”或“延后 15 分钟”。
4. 若倒计时结束无人确认，应用自动进入守护模式。
5. 守护模式保持全屏，启动前置摄像头的低分辨率、低帧率预览流；每 2–5 秒对内存中的采样帧进行本地人脸比对。
6. 只有连续多次命中同一登记儿童后，应用才进入拦截页，减少单帧误判。
7. 拦截页为黑色全屏，显示“请不要偷看他人的手机”和 PIN 输入入口。PIN 成功后，监护人可恢复守护、临时暂停或结束本次时段。
8. 时段结束，自动关闭相机、退出守护界面，并保留不含图像的本地事件记录。
9. 设备重启后，应用自动恢复已保存的守护配置并重新计算下一次时段；不在后台静默开启摄像头。首次可进入前台的时机，必须重新检查相机授权、时间规则和守护状态。

## 5. 页面与功能

### 初始设置

- PIN 创建与二次确认。
- 相机与通知权限说明及申请。
- 儿童档案：姓名/昵称、3–5 张照片、质量提示和删除操作。
- 时间规则：星期、开始时间、结束时间、是否跨午夜。

### 首页

- 下一个守护时段和当前状态。
- 开始守护、临时暂停、进入设置三个受 PIN 保护的动作。
- 最近事件摘要，仅显示时间、状态与原因，不含图像。

### 倒计时通知与确认

- 通知明确显示即将开始的规则和剩余时间。
- PIN 验证后显示“立即开始”与“延后 15 分钟”。
- 倒计时结束自动开始；一次规则最多延后一次，防止无限延期绕过。

### 守护与拦截页

- 守护页说明守护已开启，避免把相机画面裸露给用户。
- 拦截页为黑色遮罩，保留最少的提示及 PIN 入口。
- 不提供普通退出按钮或儿童可触发的暂停选项。

## 6. 技术架构

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `ScheduleService` | 计算规则、倒计时、延后与跨午夜状态 | 通知、持久化存储 |
| `BootRecovery` | 在系统允许的启动/恢复时机重载配置并重算下一次规则 | 生命周期、ScheduleService |
| `GuardianSession` | 维护守护会话、前台界面与状态机 | 调度、相机、识别 |
| `CameraSampler` | 选取前置摄像头低质量预览帧并及时释放 | HarmonyOS Camera Kit |
| `FaceMatcher` | 生成人脸特征、计算相似度、连续命中判定 | 设备端人脸识别能力/经评估的本地模型 |
| `GuardOverlay` | 显示守护页和拦截页，协调 PIN 解锁 | ArkUI |
| `SecureStore` | 加密保存照片/特征、PIN 校验值、规则与事件 | 系统安全存储 |
| `AuditLog` | 仅记录时间、状态和错误类型 | SecureStore |

模块之间仅传递最小必要数据：`CameraSampler` 输出短生命周期帧给 `FaceMatcher`；`FaceMatcher` 仅输出“无脸/未命中/连续命中/错误”状态给 `GuardianSession`；原始帧不写入文件或日志。

## 7. 状态机

`已配置 → 等待时段 → 通知倒计时 → 守护中 → 已拦截 →（PIN 成功）守护中或已暂停 → 等待时段`

- 到时段结束，无论当前是守护、拦截或暂停，均进入“等待时段”并关闭摄像头。
- 手动暂停需 PIN；暂停状态在当前时段结束后自动失效。
- 相机或权限异常进入“守护不可用”警告状态，明确告知监护人保护未生效，且不继续伪装为检测中。

## 8. 隐私与数据安全

- 参考照片和派生人脸特征均仅保存在设备加密存储中。
- PIN 仅保存加盐、慢哈希后的校验值，绝不保存明文。
- 实时帧只在内存中处理，单次比对完成后释放。
- 本地事件记录只含时间戳、守护状态、识别是否触发和错误分类；可由监护人用 PIN 清除。
- 应提供“一键删除全部儿童数据”的 PIN 保护入口。

## 9. 错误处理与限制

| 情况 | 应用行为 |
| --- | --- |
| 未授权相机 | 不开始守护，显示权限恢复说明并记录原因 |
| 摄像头被占用/不可用 | 进入明确的保护失效状态，提供重试与 PIN 暂停 |
| 识别模型不可用 | 不进入“正在保护”的假状态；要求监护人处理 |
| 弱光、侧脸或低置信度 | 保持守护，只有连续高置信命中才拦截 |
| PIN 多次错误 | 短暂冷却，记录失败次数但不记录输入内容 |
| 系统级退出路径 | 明确作为普通应用限制写入帮助页，不宣传为不可绕过的系统锁屏 |

## 10. 验收标准

- 可添加、替换和删除儿童照片；删除后相应特征同步删除。
- 可配置工作日、周末和跨午夜的时段，且计算正确。
- 时段开始时通知倒计时；1 分钟内可经 PIN 立即开始或仅延后一次 15 分钟；超时自动开始。
- 在支持的设备上守护模式使用前置摄像头低频采样，且不生成视频文件或上传网络。
- 连续命中登记人脸后显示全屏黑色拦截页；未命中或仅单帧命中不拦截。
- PIN 是解除拦截、暂停和修改设置的必要条件；错误 PIN 不能改变守护状态。
- 相机授权、占用或识别模块异常时，界面明确显示“保护未生效”。
- 时段结束能释放相机资源、退出守护状态，并仅保存无图像的事件摘要。
- 设备重启后，已保存的规则仍存在且下一时段被重新计算；应用不得在未获授权或后台不可见状态下静默打开摄像头。

## 11. 实施前验证项

在正式开发前，以目标 HarmonyOS NEXT 设备和计划采用的 SDK/API 版本验证：

1. 到点后从非前台状态唤起倒计时/守护流程的系统限制与用户可见行为。
2. 前台全屏守护页下前置摄像头预览流的持续稳定性、功耗和发热。
3. 设备端可用于本地人脸比对的正式 API 或合规第三方离线模型的可用性、性能和应用分发限制。
4. 通知、全屏显示、返回手势和系统窗口在不同机型/系统版本上的实际拦截边界。
5. 目标设备与 SDK 是否提供普通第三方应用可用的开机恢复回调；若不可用，产品采用系统允许的最早恢复时机重载规则，并在首次启动时明确提示监护人。不得以自启名义绕过系统限制。

这些验证结果可能要求调整启动体验或识别实现，但不改变“本地处理、无视频留存、PIN 解除、普通应用不承诺系统锁屏”的产品边界。
